# 数据集 trace 复杂度分布

四数据集各自的 trace 复杂度分布(纯数据,无 pass@1)。`python -m data.diag.dataset_dist`。
benchmark = cruxeval / mbpp / humaneval,训练主体 = pyx;frac = 源内占比。四轴:
`frames`=LINE 帧数,`nvars`=局部变量名数,`locals_len`=每帧 locals 平均 **token** 数,
`trace_len`=整条 trace 的 **token** 数(= cache `trace_ids` 长度)。token = precompute tokenizer
(Qwen2.5-Coder-1.5B + trace tokens)。

## 结论
1. **训练分布比 eval 难。** pyx(占 95%)四轴偏高(21+ 帧 .381、变量=4 .345、locals 16+ tok .640、
   trace ≥1024 tok .327),而 cruxeval 短(21+ 仅 .130、变量峰 2–3、trace 过半 <256 tok .555)。
   模型在比测试更长更宽的状态上训练。
2. **印证 H1/H2。** A/A2 中 CODI 崩得最狠的 21+ 帧、中等复杂度箱,恰是训练**最密集**处(pyx 21+ .38、
   locals 16–23 tok .459)。训练量最大却表现最差 → 非数据稀缺,是 latent 表示容量瓶颈。
3. **早期样本无明显分布漂移。** first 15%/30% 的 21+ 帧、nvars=4、locals 16–23、trace_len 各箱
   基本贴近 train-used,因此“没用完整数据集”不改变上述训练分布判断。
